# Contribuindo com o Vesper

Este documento define as convenções de contribuição do projeto. Elas valem para
todo mundo que abre uma branch aqui.

*This document defines the project's contribution conventions. They apply to
everyone who opens a branch here.*

---

## Branches

Toda branch começa com um prefixo de tipo, seguido de `/` e um slug descritivo
em pt-BR com palavras separadas por hífen.

*Every branch starts with a type prefix, followed by `/` and a descriptive
slug in pt-BR with words separated by hyphens.*

```
<tipo>/<slug-descritivo>
```

Os tipos permitidos são exatamente os mesmos types usados no commit — o
mapeamento é 1:1, sem exceção. Uma branch `feat/x` produz commits `feat: ...`.

*The allowed types are exactly the same types used in the commit — the mapping
is 1:1, with no exceptions. A `feat/x` branch produces `feat: ...` commits.*

| Prefixo | Quando usar | Exemplo |
|---|---|---|
| `feat/` | Funcionalidade nova | `feat/coletar-eventos-eventbridge` |
| `fix/` | Correção de bug | `fix/timeout-lambda-watch` |
| `docs/` | Documentação, tradução, ADR | `docs/traduzir-readme-pt-br` |
| `chore/` | Tooling, config, dependências | `chore/atualizar-gitignore` |
| `refactor/` | Reestruturação sem mudar comportamento | `refactor/extrair-cliente-boto3` |
| `test/` | Testes | `test/integracao-repair-ec2` |

Não use `feature/`. O prefixo é `feat/`, igual ao commit type.

*Do not use `feature/`. The prefix is `feat/`, matching the commit type.*

```bash
git checkout -b docs/traduzir-readme-pt-br
```

## Commits

O projeto usa [Conventional Commits](https://www.conventionalcommits.org/) com
o subject em pt-BR.

*The project uses [Conventional Commits](https://www.conventionalcommits.org/)
with the subject in pt-BR.*

```
docs: traduzir README para pt-BR
feat: coletar eventos do EventBridge
```

Mensagens de commit nunca incluem atribuição de IA — `Co-Authored-By` de
modelos, "generated by", nome de modelo. O histórico deve ler como escrito
pelos autores humanos do projeto.

*Commit messages never include AI attribution — model `Co-Authored-By` lines,
"generated by", model names. The history must read as written by the project's
human authors.*

## Documentação

Toda documentação em markdown é escrita em pt-BR, seguida de um espelho em
itálico em en-US.

*All markdown documentation is written in pt-BR, followed by an italicized
mirror in en-US.*

O espelho cobre **apenas a prosa**. Diagramas ASCII, blocos de código, tabelas
de referência técnica e estruturas de diretório aparecem uma única vez — são
idênticos nos dois idiomas e duplicá-los só cria duas cópias para manter em
sincronia.

*The mirror covers **prose only**. ASCII diagrams, code blocks, technical
reference tables, and directory structures appear once — they are identical in
both languages, and duplicating them only creates two copies to keep in sync.*

Termos técnicos permanecem em inglês dentro do texto em pt-BR: *state file*,
*failover*, *drift*, *runtime*, nomes de serviços AWS.

*Technical terms stay in English inside pt-BR text: state file, failover,
drift, runtime, AWS service names.*

Código, identificadores e strings visíveis ao usuário nas aplicações continuam
em en-US. A regra bilíngue vale para documentação, não para código.

*Code, identifiers, and user-facing strings in the applications remain in
en-US. The bilingual rule applies to documentation, not to code.*

### ADRs

Decisões arquiteturais ficam em `docs/adr/`, nomeadas `ADR-NNN-<slug>.md`, com
as seções Contexto → Decisão → Motivos → Consequências. Cada seção segue o
mesmo padrão bilíngue.

*Architecture decisions live in `docs/adr/`, named `ADR-NNN-<slug>.md`, with
the sections Context → Decision → Reasons → Consequences. Each section follows
the same bilingual pattern.*

Uma decisão registrada em ADR só é revertida por um novo ADR. Não reintroduza
uma opção rejeitada sem abrir um.

*A decision recorded in an ADR is only reversed by a new ADR. Do not
reintroduce a rejected option without opening one.*
